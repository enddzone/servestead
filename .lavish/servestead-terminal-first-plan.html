The course change

The TUI already covers the important workflows. The local browser mostly duplicates them and adds build, security, documentation, and maintenance work.

Today

Two local interfaces

  • servestead ui runs HTTP, auth, CSRF, htmx, SSE, and browser launch code.
  • servestead setup already handles setup, stacks, Git actions, secrets, cloud actions, progress, and retries.
  • Docs call the browser the default even though provisioning is safer and richer in the terminal.
  • TUI tests drive models directly, but no test runs a full Bubble Tea program or a real terminal.
Target

One interactive interface

  • servestead setup is the primary interactive command.
  • Direct CLI commands remain available for scripts and recovery.
  • The Astro site remains documentation only. Pangolin, Beszel, Dozzle, and Dockhand remain managed remote services.
  • Program tests, view checks, and one PTY smoke test cover the terminal behavior before live infrastructure is touched.

Target shape

The change removes the local browser adapter. It does not replace or rewrite the server lifecycle.

Safety work comes before deletion

The current TUI has real operational hazards. Color and spacing can wait until these are fixed.

!

Four blockers for a trustworthy terminal test

Each item gets a fake-backed regression test before implementation changes proceed.

Cancel does not cancel cloud work Ctrl+C quits the interface, while provisioning keeps its original context and profile cloud actions use context.Background().
A save failure can create a second Droplet If DigitalOcean creation succeeds but local profile persistence fails, the UI returns to Review. Pressing Enter calls create again.
Local deletions are too easy Stack and profile deletion accept one y. They should require the exact name, show the path and effect, block active runs, and keep errors inside the TUI.
The current macOS test path reads real profiles os.UserConfigDir() ignored temporary XDG_CONFIG_HOME during inspection. Add one Servestead config-root override used by profile and repository defaults.

Implementation order

Each phase ends with a behavior check and can be reviewed as a focused commit. Web removal waits only for safety guards and run-history preservation.

0
Guardrails

Isolate test data and record the baseline

Make it impossible for program and PTY tests to load real profiles or create real repositories.

  • Add SERVESTEAD_CONFIG_DIR as the explicit Servestead root. Use the same resolver for profile and default repository paths.
  • Inject ProfileStore, fake providers, and recording remote clients into program-level tests.
  • Add fixed-size view checks and a Unix PTY helper process. Normalize ANSI, paths, IDs, and timestamps.
  • Treat q from navigation as a clean exit, with exit code 0 and no error: setup cancelled.
Phase checkA temporary config root starts empty on macOS. Startup, resize, q, Esc, and Ctrl+C restore the alternate screen and cursor without a hang. Existing real profiles never appear.
1
P0 safety

Make asynchronous and destructive actions honest

The UI must do exactly what its status and help text claim.

  • Give provisioning, cloud actions, Git work, and run commands cancellable child contexts.
  • Keep a Cancelling state visible until the command acknowledges cancellation. Persist cancelled, not failed.
  • Carry the created Droplet ID and IP through a local save failure. Retry persistence only. Never call provider Create twice.
  • Require typed stack and profile names for deletion. Show the exact local path and remote effect. Block profile deletion while a run is active.
Phase checkDelayed fakes observe context cancellation. Provider call counts stay at one across save retry. Failed local deletion leaves the user in place with an actionable error.
2
Parity

Move persisted run history into the TUI

This is the one meaningful browser-only capability that should survive.

  • Extract JSONL parsing, secret masking, and run-log loading into neutral backend code.
  • Add a read method to ProfileStore. Do not downcast to *fileProfileStore.
  • Add a compact runs list and detail viewport to the profile TUI. Show status, timestamps, stage error, redacted log text, and the underlying log path.
  • Port only the generic parser and masking tests from the web test file.
Phase checkSeeded secrets never appear in frames, terminal output, or history detail. Malformed JSONL lines fail clearly. Existing profile logs remain readable without migration.

Removal

Delete the local web interface and its toolchain

Remove the isolated adapter, not the shared product code.

  • Delete the three backend web files and all of frontend/.
  • Remove servestead ui from usage, dispatch, and CLI tests.
  • Run go mod tidy. Remove the direct templ dependency and tool directive.
  • Remove templ generation, generated diff, and frontend asset checks from CI, CodeQL, release, security, GoReleaser, and the release Dockerfile.
  • Remove old web plans and mockups. Browser documentation screenshots move in Phase 5.
Phase checkrg finds no imports of servestead/frontend, web symbols, templ commands, or direct browser launcher code. go test ./... and a release build pass.
4
Polish

Make the TUI consistent, responsive, and calm under work

Fix interaction and state flow before applying the final visual treatment.

  • Use one keymap for handling and help. Focused text fields and filter inputs receive printable keys first.
  • Show one footer, with ? for expanded help. Remove the nested list help duplication.
  • Move blocking Git and repository work out of Update into typed commands with visible busy states.
  • Make layout dimensions terminal-driven. Keep errors and primary actions visible and add a clear minimum-size screen.
  • Stop forcing logs to the bottom while the user scrolls. Resume follow-tail on End and report queued new lines.
  • Use semantic styles for selected, muted, warning, error, success, and progress states. Keep text labels so color is never the only signal.
Phase checkView checks pass at 40x12, 80x24, and 120x40. Printable token characters work. Review help matches behavior. Complete, Failed, and Cancelled runs show the right final state.

What polish means here

This is behavior work with a visual finish, not a theme-only pass.

Interaction

Keys and focus

GitHub token fields currently swallow printable e, x, and d. Provisioning lists intercept filter keys. Review claims q quits when it does not.

  • Component-first input routing
  • Canonical key bindings shared by Update and help
  • Clean quit distinct from operational cancellation
Layout

Real terminal sizes

Several tables force 78 columns, inputs force 72, and errors can land below the visible body.

  • Responsive columns and display-width truncation
  • Viewport-backed long screens
  • Minimum-size message below the supported layout
Busy states

No frozen interface

Diff, stage, commit, push, save, repository refresh, preflight, and repository preparation can block before a useful status appears.

  • Typed command result messages
  • Spinner, operation name, and duplicate-action lock
  • One run timeline beginning before remote SSH
Run view

Logs that can be read

New lines currently force the viewport to the bottom, so scrolling cannot hold while output continues.

  • Follow-tail state with End to resume
  • Queued-line count while paused
  • Current task cleared on terminal states

The full TUI test run

A full test has three distinct lanes. The first two are mandatory. The live infrastructure lane requires fresh authority and a disposable target.

Mandatory

Program and model tests

Fast, deterministic, no network.

  • Existing 74 setup and 17 provisioning tests
  • Full Bubble Tea program input/output tests
  • Fake cloud and recording SSH clients
  • View checks at three terminal sizes
  • Cancellation and duplicate-create regressions
Mandatory

Real terminal smoke

Actual key decoding and renderer lifecycle, still no network.

  • Unix PTY helper process
  • Alternate-screen and cursor restoration
  • Resize, filter, Esc, q, Ctrl+C
  • Temporary SERVESTEAD_CONFIG_DIR
  • Provider credentials removed from the environment
Separate approval

Disposable VPS acceptance

Real SSH, Docker, firewall, DNS, and remote services.

  • Existing disposable Ubuntu 22.04+ VPS preferred
  • ED25519 key plus apex and wildcard DNS
  • Bootstrap, Harden, Platform, rerun, and QA stack
  • DigitalOcean create/restart/destroy is a second explicit gate
